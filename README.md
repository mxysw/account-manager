# Account Manager（本机浏览器版）

一个本地自托管的 Google 账号管理与浏览器自动化面板。它可以批量导入账号、生成 TOTP 验证码、记录检测状态、自动分类，并使用本机 Chrome 或 Edge 执行登录、检测和维护流程。

> 当前研发重点是“本机临时浏览器”模式。AdsPower 兼容代码仍然保留，但暂不作为维护、测试和文档重点。

## 功能概览

- 本地 JSON 存储，不依赖数据库服务。
- 批量导入账号，按邮箱去重，重复导入只补全空字段。
- 自动填写邮箱、密码、TOTP 或确认辅助邮箱地址；遇到人机验证、邮箱验证码、短信验证、安全密钥或高风险验证时停止并提示人工处理。
- 每个并发槽启动独立的一次性 Chrome/Edge 配置，任务结束后默认关闭并清理。
- 检测结果逐项写回账号库，可归入养号、废号、登录失败、待人工、密钥错误、出售和已售等视图。
- 支持单账号运行和批量运行；行内“检测”会复用批量操作面板的当前配置。
- 提供“仅验证账号密码”独立检测：密码页只提交一次，密码通过后立即停止，不进入 2FA、短信或设备验证。
- 内置 Gmail/YouTube 封禁、服务限制、地区、GPT、Gemini 等检测，以及语言、2FA、设备、验证电话、年龄和支付资料等维护动作。
- 提供本地手机号池，支持“共享号码”和“一号一绑”两种分配模式，并可从指定模式的池中原子领取号码添加到 Google 两步验证。

## 环境要求

- Windows 10/11。
- Node.js 22.12.0 或更高版本。
- npm。
- Google Chrome；找不到 Chrome 时会自动尝试 Microsoft Edge。
- 可以访问动作所需的网站。

本机模式不需要安装或启动 AdsPower，也不需要 AdsPower API Key。

## 安装与启动

~~~powershell
git clone https://github.com/mxysw/account-manager.git
cd account-manager
npm ci
npm start
~~~

启动成功后打开：

~~~text
http://127.0.0.1:8910
~~~

开发时可以使用自动重启：

~~~powershell
npm run dev
~~~

如果 Chrome/Edge 不在常见安装位置，请在启动服务前指定浏览器路径：

~~~powershell
$env:LOCAL_BROWSER_PATH = 'D:\Apps\Chrome\chrome.exe'
npm start
~~~

端口被占用时可以临时更换：

~~~powershell
$env:PORT = '8911'
npm start
~~~

除非你已经自行增加认证和网络隔离，否则不要把 `HOST` 改为 `0.0.0.0`。默认的 `127.0.0.1` 只允许本机访问。

## 导入账号

进入“检测系统” → “导入账号”，每行粘贴一个账号。前两项固定为邮箱和密码，后续字段会自动识别。

没有辅助邮箱和验证器、只需账号密码登录时，可直接使用冒号格式：

~~~text
user@example.com:password
~~~

冒号格式只把第一个冒号作为分隔符；密码里后续的冒号会原样保留。

使用 `|` 分隔：

~~~text
user@example.com|password|BASE32_TOTP_SECRET|2025|US
~~~

使用 `----` 分隔：

~~~text
user@example.com----password----recovery@example.com----BASE32_TOTP_SECRET----2025----US
~~~

只需确认辅助邮箱地址的账号也可以直接导入，不要求 TOTP 密钥：

~~~text
user@example.com|password|recovery@example.com
user@example.com|password|recovery@example.com|FA
~~~

导入规则：

- 至少需要“邮箱 + 密码”。
- 纯账号密码可写成 `邮箱:密码`，辅助邮箱和 TOTP 会留空。
- 后续字段顺序可以变化：包含 `@` 的字段识别为辅助邮箱；四位年份识别为注册年份；Base32 字符串识别为 TOTP 密钥；短英文字符串识别为国家或地区。
- 辅助邮箱为空时可以写 `空` 或 `?`。
- 辅助邮箱账号末尾的 `FA`（不区分大小写）只作为来源标记忽略，不写入国家或 TOTP 密钥；邮箱中的 `\@` 会还原为 `@`，密码不做该替换。
- TOTP 密钥中的空格和连字符会自动移除。
- 邮箱去重不区分大小写；重复导入不会覆盖已有值，只补全空字段。
- “货源渠道 / 标签”会写入本批新账号，旧账号仅在该字段为空时补入。

示例均为占位符。不要把真实凭据写进 README、Issue 或 Git 提交记录。

## 使用本机浏览器模式

第一次使用时，建议只用一个你自己拥有的测试账号：

1. 在“检测系统”导入账号，确认邮箱和密码；账号若启用了 TOTP 或辅助邮箱确认，再检查对应字段齐全。
2. 展开顶部“批量操作（本机浏览器优先）”。
3. 选择“本机临时浏览器（推荐，用完即弃）”。新安装默认就是该模式。
4. 把并发数设为 `1`，稳定后再逐步增加。每个并发槽都会启动一个独立浏览器进程。
5. 勾选账号，再按执行顺序勾选动作。本机浏览器没有历史登录态，通常应先选“登录账号”，再选检测或维护动作。
6. 点击“对选中账号运行”。只运行一行时，可以点击该账号行内的“检测”。
7. 在运行日志中查看结果；每个动作完成后，状态会立即写回账号库。
8. 需要中断时点击“停止并关闭窗口”。
9. 检测完成后可使用“一键分类”把账号归入对应管理视图。

推荐的首次验证顺序：

1. 单账号、并发 `1`、仅运行“登录账号”。
2. 登录稳定后，增加 Gmail/YouTube 封禁、服务限制、地区等低风险检测。
3. 最后再单独验证改语言、换 2FA、移除设备/电话、年龄验证或关闭支付资料等写操作。

### 纯账号密码登录

使用 `邮箱:密码` 导入后，照常选择“登录账号”。这类记录的辅助邮箱和 TOTP 字段为空；如果 Google 接受密码且没有发起额外验证，程序会直接完成登录，不会寻找验证器。

如果 Google 因账号安全策略临时要求验证码、设备确认、人机验证或其它二次验证，程序仍会停止并提示人工处理，不会绕过 Google 的验证要求。

### 辅助邮箱登录

导入后仍选择“登录账号”，无需另外选择登录模式。Google 要求“确认您的辅助邮箱”时，程序填写导入的辅助邮箱地址并继续；无需为这类账号填写 2FA 密钥。原有身份验证器 TOTP 登录仍可使用。

没有 TOTP 密钥时，验证方式列表会选择“确认辅助邮箱”（含简写），不会选择身份验证器；若 Google 默认进入验证器页面，会有限尝试“试试其他方式”再选择辅助邮箱确认。选择后会核对页面是否推进，不能切换时停止并提示，不会一直空转。数字密码的前导零会原样保留。

“确认辅助邮箱地址”和“输入发到邮箱的验证码”是两种验证：后者会标记“需邮箱验证码”，交由人工处理，不会访问辅助邮箱站点或尝试收信。辅助邮箱缺失、填写错误分别显示“缺少辅助邮箱”“辅助邮箱错误”，复制或导出异常账号时也会带上对应原因。人机验证和人工处理窗口仍按上方的关闭/保留选项执行。

### 仅验证账号密码

需要只核对账号库里的密码是否有效时，单独勾选“仅验证账号密码（密码通过即停止，不进入2FA）”。该动作会自动与其它动作互斥，并且：

- 只需要邮箱和密码，不要求账号库已有 TOTP 密钥。
- 邮箱步骤正常提交；密码页“下一步”只提交一次，避免错误密码被反复尝试。
- Google 接受密码并跳到 2FA、手机确认、短信验证或其它后续页面后，立即记录“密码正确”并停止，不点击后续页面、不填写验证码。
- 明确出现“密码错误”或“密码已更改”时写回对应原因；Google 提供更改时间时会直接显示“密码已更改（4天前）”。人机验证、浏览器拦截或超时只显示“无法确认”，不会误报密码错误。
- 结果以小标签显示在账号行的密码旁边。该结果独立于完整登录状态，不会把只通过密码页的账号错误归入养号或出售。

### 原号检测（Cloud 电话验证）

在批量操作中选择“登录账号”→“原号检测（Cloud 电话验证）”，并发数和窗口保留策略沿用上方设置。已有登录态时可只选检测。

- 程序打开 Cloud 控制台、Cloud Shell，再进入电话验证方式；到号码页面即停止，不填写号码、不发短信、不更改安全设置，也不开通免费试用或计费。
- 支持中英文及韩文电话验证入口；遇到无法识别的验证页时，最多尝试一次切换当前页面为简体中文，不修改账号语言设置。仍无明确证据时保留“未确认”。
- Cloud 首页的“近期查看过”“生产环境”新手提示会先安全关闭，再查找终端；条款、授权及未知弹窗不会被自动关闭。
- 首次使用 Cloud 如需地区/条款确认，默认停止并提示。只有勾选“首次 Cloud 使用：同意条款并继续”后，才会核对账号并沿用页面已选地区同意条款；地区为空时仍需手动选择。
- “需原号”：Google 明确要求确认已添加的号码，或使用页面列出的已有号码收码。
- “可填新号”：本次验证明确允许输入新号码。这个信号不能证明该账号历史上从未绑定过手机号。
- “需扫码”：进入要求手机扫码并返回电脑继续的验证页时立即记录，不扫描二维码、不等到通用超时。此结果仍属于“未确认”筛选，不能据此判断是否绑定手机号；仅含扫码选项的验证方式列表不会被误当作扫码页。
- “Shell 可用”：已直接进入终端，本次无需手机号验证；未触发原号核验，无法判断是否绑定原号。
- “Shell 已停用”：页面明确表示 Cloud Shell 已停用、暂停或封禁，无法通过此入口检测原号；手机号状态未知，不代表整个 Google 账号被封禁。
- “Shell 不可用”：服务不可用或账号不符合使用资格，导致原号检测受阻，手机号状态未知；不能据此认定账号被封禁。仅要求 API 授权则显示“Shell 待授权”，检测未继续，也不会自动授予权限。
- 账号行在 Shell 标签下直接显示检测含义，不必悬停；日志与复制内容提供完整原因及手机号判断边界。旧记录按原因码直接展示新说明，无需重新检测，不改写历史结果。
- 上述 Shell 状态与“需扫码”仍归入“未确认”筛选。没出现电话验证、人机验证、其他验证或页面异常，也不当作“没有原号”。
- 账号表的“原号检测”短列显示结果，悬停可看原因和检测时间；账号库可按结果筛选。不会根据该结果自动删除账号或更改出售分类。
- 单行复制、复制选中及交付导出会在账号字段后追加简短原号检测结果，如 `----原号检测：可填新号（本次验证）`；已有异常原因继续保留，未检测账号保持原格式。

### 添加身份验证器（无本地 2FA 密钥的账号）

勾选待处理账号，单独选择“添加身份验证器（未设置账号）”后运行。程序会先登录，再检查 Google 的验证器设置；不要求事先导入 TOTP 密钥，并发数和人工验证窗口策略沿用上方设置。

- 本地没有密钥不等于 Google 没有验证器。页面若显示已有验证器，只标记“已有验证器”，不会替换或删除；需要更换时使用原有“更改 2FA”动作。
- 新设置只有在 Google 接受验证码并明确确认添加后，才保存新密钥；完整完成后显示“已添加”。若密钥已保存、但尚未确认 Google 两步验证总开关开启，会显示“密钥已保存·开启待确认”：这一步已保留可用密钥，开启结果还需确认。已保存的密钥复用 2FA 列的“取码”和双击脱敏密钥复制功能；未确认的新密钥和未取得的已有密钥不会出现在结果标签中。
- 辅助邮箱登录和直接账号密码登录使用同一收尾流程：保存验证器后进入两步验证页，点击明确的开启按钮，处理开启确认与完成提示，并核对同一账号出现“关闭两步验证”或“You’re now protected with 2-Step Verification”完成弹窗。该完成弹窗表示已经开启，`Done` 仅尝试点击一次关闭提示，不影响已确认的结果。没有明确成功证据且页面反馈滞留时，最多重新打开一次设置页复核，不重复提交开启。对“密钥已保存·开启待确认”的账号再次运行本动作，只复核或补开总开关，不重新生成或替换密钥。
- 开启时若出现“Add a phone number for 2-Step Verification?”且提供明确的“Skip”，程序只点一次跳过，不添加手机号；跳过后仍须复核总开关。强制手机号验证、要求填写号码/验证码或没有跳过按钮的页面仍交给人工处理。
- 登录、添加验证器、开启两步验证分别保留各自结果。登录成功后，如果设置页再次要求身份确认或出现无法确认的页面，不会把此前的“登录正常”改写成登录失败。尚未确认密钥添加成功时显示“设置需处理”或“添加失败”；已经确认并保存密钥后遇到阻碍，显示“密钥已保存·开启待确认”。“设置需处理”不代表已添加密钥，具体原因和停止阶段可查看日志或悬停 2FA 列的标签；不会把未完成的设置报为成功。

### 添加两步验证手机号

1. 展开“手机号池”，先选择“导入为”，再按“一行一个”导入带国家码的 E.164 号码，例如 `+12025550123`；可以在 `|` 后附备注。
2. 运行前在手机号池选择“本次添加使用：共享号码 / 一号一绑”。这个偏好会保存在当前浏览器，默认使用共享号码；自动化只会从所选模式的池中领取。
3. 只勾选一个或多个待处理账号，并单独选择“添加两步验证手机号”。这个写操作与其它动作互斥，账号并发数遵循上方“并发数 / 最大并发”设置。
4. 程序会为每个账号原子领取号码，登录并进入 Google 的两步验证手机号页面：填写号码后点一次 `Next`，核对确认页中的目标号码后再点一次 `Save`。只有 `Save` 才视为真正提交，两个按钮都不会重复点击。
5. 只有 `Save` 之后 Google 明确显示添加成功、提示 `security delay` / 稍后生效，或目标号码已出现在列表中，才记录本账号绑定成功。若要求短信验证码、人机验证、页面超时或明确失败，本账号会记录具体失败原因，然后继续处理下一个账号。
6. 成功后，“邮箱 / 密码”右侧的“2FA 手机号”短列会显示脱敏号码，点击即可复制完整号码。短标签使用“新增 / 已有 / 绑定 / 免验 / 已验 / 待生效”；历史记录无法确认来源时只显示“绑定”，不会猜测。
7. 共享模式下，无论本账号成功还是失败，任务结束都会解除本次占用；号码立即重新显示为可用，不会因为一个失败账号卡住整批任务。

如果 Google 另行要求短信验证码，程序不会把账号的身份验证器动态码误填进去；当前账号会结束并记录原因，只释放当前账号的号码占用，不影响其它并发任务。

两种模式的区别：

- **共享号码**：同一个号码可按顶部并发数同时尝试多个账号。成功会累计“已绑 N”；失败、超时、短信验证或人机验证也会立刻结束本账号，不影响其它并发账号。本地手机号池不限制共享复用次数。Google 自身对同一号码的绑定次数、频率和账号风险有独立限制，仍可能要求验证或拒绝，这不属于本地次数限制。
- **一号一绑**：一个号码只分配给一个账号；成功使用后显示“一号一绑·已用”，不再进入可领取集合。

已绑定的号码仍可在手机号池中勾选和管理。共享号码可以在状态下拉框中选择“停用复用”，需要继续分配时再选择“恢复共享可用”。任务运行时会显示“共享可用（并发 N）”，每个账号结束时只释放自己的占用。若旧任务异常中断，服务重启会自动恢复；紧急情况下也可在号码行明确“释放全部 N 个占用”。删除已有绑定记录时页面会再次确认，并向后端明确请求强制删除绑定记录；该操作**只删除本地手机号池记录，不会从 Google 账号中解绑手机号**。

完整手机号不会随账号列表下发到浏览器，也不会写入页面文本、悬停提示或 HTML 属性；只有点击对应脱敏号码时，后端确认该账号确实绑定了该号码后才返回并复制。若“移除两步验证手机号”在 Google 页面确认号码已移除或本来不存在，本地账号行也会同步停止显示该绑定。

一号一绑模式仍采取保守策略：可能已经提交但尚未确认的号码会保持“待生效 / 待确认”，避免把同一个独享号码错分给别的账号。共享模式则以批量吞吐为优先，任何终态都会继续下一账号。

### 本机模式的行为

- 自动优先查找 Chrome，找不到时回退到 Edge；可以用 `LOCAL_BROWSER_PATH` 覆盖。
- 每个账号任务使用新的临时用户数据目录，通常位于 `%TEMP%\am-local-*`。
- 默认在任务结束后关闭浏览器并删除临时目录。
- 勾选“后台运行（最小化）”后，检测窗口会尽量保持最小化并留在任务栏；不会改用无界面浏览器，也不影响检测步骤。程序不再主动把保留窗口的账号标识页切到前台，新开的检测页面也会尝试最小化。该偏好保存在当前管理页面的浏览器，下次批量或单行检测共用。
- 后台运行与“普通跑完保留”“人机/需人工验证”策略独立：应关闭的仍然关闭，应保留的留在任务栏，可手动打开查看；“停止并关闭窗口”行为不变。系统弹窗或不支持窗口控制的浏览器仍可能短暂显示，最小化失败会在对应任务中提示，不伪报检测失败。
- AdsPower 兼容路径仅在接管后控制窗口，不覆盖环境已有启动参数；启动阶段仍可能短暂显示。实现依据 [CDP 窗口控制协议](https://chromedevtools.github.io/devtools-protocol/tot/Browser/#method-setWindowBounds)；AdsPower 启动参数的覆盖规则见[官方说明](https://localapi-doc-en.adspower.com/docs/FFMFMf)。
- “跑完保留窗口”控制普通完成窗口；旁边的“人机/需人工验证”下拉框单独控制异常现场，默认“检测后关闭”，也可选择“保留窗口”。两种选择都会把账号记录为人机/需人工，区别只在窗口是否留下。添加手机号批次的普通完成始终自动关窗，以免已完成账号占满并发槽位。
- 本机模式暂未在界面中接入代理，当前按直连使用。
- 本机模式不使用 AdsPower 环境编号或 AdsPower 随机指纹。

## 账号管理流程

- “检测系统”：导入、编辑、运行检测和一键分类。
- “养号管理”：保存状态正常但尚未达到出售标准的账号。
- “废号管理”：收纳 Gmail、YouTube 或 GPT 已封禁的账号。
- “登录失败 / 待人工 / 密钥错误”：分别处理密码失败、额外验证和 TOTP 异常。
- “出售管理”：集中处理待交付账号，导出时可标记已售。
- “已售记录”：查询已交付账号，并支持误操作后退回在库。

复制或导出账号时会把凭据放入系统剪贴板，使用完毕后请及时清理剪贴板。

## 数据文件与备份

运行数据保存在：

~~~text
data/accounts.json   账号、密码、TOTP、辅助邮箱、状态和备注
data/cards.json      卡号、有效期、CVC 和使用状态
data/phones.json     两步验证手机号、占用账号和验证状态
data/cookies.json    已保存的会话 Cookie（如有）
~~~

这些文件包含敏感信息，已被 `.gitignore` 排除。GitHub 只备份代码，不会、也不应该备份真实运行数据。

备份前先在运行服务的终端按 `Ctrl+C` 正常退出，然后在项目目录执行：

~~~powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$backupDir = Join-Path (Split-Path $PWD -Parent) "account-manager-data-$stamp"
Copy-Item -LiteralPath '.\data' -Destination $backupDir -Recurse
Write-Host "已备份到 $backupDir"
~~~

恢复时先停止服务，并先保留当前数据，再把备份中的 JSON 文件复制回 `data/` 后重新启动。

前端选择、筛选和运行模式等偏好保存在浏览器 `localStorage` 中；任务队列和运行日志只存在于当前服务进程内，不包含在上述数据备份中。

## 常见问题

### PowerShell 提示找不到 `node` 或 `npm`

安装 Node.js 22.12+，重新打开 PowerShell，然后检查：

~~~powershell
node --version
npm --version
~~~

### 提示“未找到本机浏览器”

安装 Chrome/Edge，或在启动服务前设置 `LOCAL_BROWSER_PATH`。路径必须指向浏览器可执行文件，而不是快捷方式。

### 提示“未安装 puppeteer-core”

不要使用 `--omit=optional`，然后重新安装依赖：

~~~powershell
npm ci
npm ls puppeteer-core
~~~

### 浏览器打开了，但没有自动登录

本机模式使用全新临时配置，没有历史登录态。请确认勾选了“登录账号”，并确认邮箱、密码正确；账号若启用了 TOTP 或辅助邮箱确认，再检查对应字段是否齐全。

### 登录显示“待人工”或“2FA 密钥错”

短信验证、Google Prompt、安全密钥、验证码或可疑活动验证会按设计停止。需要查看现场时，可在运行前勾选“跑完不关闭窗口”。“2FA 密钥错”应先人工核对密钥和系统时间。

### CAPSOLVER 登录人机验证

本机浏览器模式把“登录账号”作为首个操作，可接续后续操作（仍需遵守各操作的独立运行限制），启用 **CAPSOLVER**；也可只勾选“添加身份验证器”，支持该操作内部登录及重新验证时的人机挑战，无须另选“登录账号”。“添加身份验证器”仍须单独运行，不能与其他操作混选；其内部登录、重新验证及重试共用同一个账号的打码次数，不会重新分配额度。API Key 首次保存到本机后自动复用，刷新页面、后续批次及服务重启都不必重新输入；可随时更换或清除。密钥使用当前 Windows 用户的 DPAPI 加密，独立保存在 `data/capsolver-settings.json`（已忽略 Git），不会放入账号文件、浏览器存储或接口响应。加密文件需由原 Windows 用户使用，不能直接复制到另一台电脑/另一个用户解密；加密失败时不会退回明文保存。每个任务结束会释放该任务的内存副本，不会删除本机配置。清除配置不影响已经开始的任务；需要同时停止正在执行的任务。

保存密钥不等于启用付费打码。可手动勾选 CAPSOLVER，或在“人机/需人工验证”选择第三项“自动打码，完成后关闭”，后者会自动启用 CAPSOLVER 并使用已保存的 Key。登录验证通过后继续后续操作；未通过则记录结果并跳过后续步骤。第三项在完成或失败后都关闭窗口，优先于“跑完保留窗口”。短信、设备确认及“添加身份验证器”以外后续操作中的再次验证不会自动处理。开关和“每账号最多打码次数（含首次）”作为非敏感偏好保留；次数默认 3，可设为 1–10。每个账号独立计次，成功即停止重试：例如 10 个需要打码的账号设为 3，最多共调用 30 次，其他账号用完次数不影响当前账号。旧版整批额度不会被误用为单个账号额度，升级后首次采用默认 3 次并保留开关状态。暂不支持代理模式。

启用后先点击一次人机复选框，直接通过不调用云端，也不扣打码次数。仅处理能明确识别并绑定到当前账号的 reCAPTCHA v2/Enterprise v2；向官方 API 发送页面路径（无登录查询参数）、站点公钥和挑战参数，不发送密码、2FA 密钥或 Cookie。拿到令牌不代表登录成功：仍需 Google 实际接受并完成登录。失败后，仅在当前账号仍有可识别的挑战且未达到次数上限时重新打码；不能识别、账号停用或拒绝登录、要求手机号或短信、配置或余额错误会提前结束，按“人机/需人工验证”策略保留或关闭窗口。进度会显示当前账号实际发起的调用次数；检查复选框、排队或仅轮询已有结果不另计次数。停止会中断本地等待，但不能撤销已提交给平台的任务及可能产生的费用。

启用后会在新登录页加载前观察公开的 reCAPTCHA `render` 调用，以匹配该控件实际注册的完成回调，不遍历 Google 私有回调对象。旧页面需重新运行登录才能获得这项观察。进度徽标悬停可查看固定的回调类别和调用状态；这只是提交诊断，不代表 Google 已接受结果，也不保证每个账号都能自动通过。

登录仍按实际页面执行：没有人机时正常登录；人机通过后继续密码、身份验证器动态码或辅助邮箱确认。若随后要求添加手机号或验证原手机号，账号行与日志分别显示“人机后需添加手机号”或“人机后需手机验证”，停止该账号后续操作，并按窗口策略收尾（第三项会关闭）。不会填写电话号码、发送短信或把 TOTP 填入短信验证码框；没有经过人机的手机号关卡不加“人机后”前缀。

### 浏览器跑完自动关闭

这是默认行为。普通结果需要保留时勾选“跑完保留窗口”；只想在人机、设备通知、短信或其它需人工验证时保留，则把“人机/需人工验证”改为“保留窗口”。保留后请自行关闭窗口，并清理不再需要的 `%TEMP%\am-local-*` 目录。

### 服务重启后任务不见了

任务队列和日志保存在内存中，服务重启后会丢失；已经完成的动作状态会逐项写回 `data/accounts.json`。

### 本机模式如何配置代理

界面目前尚未接入本机代理配置，因此本机模式暂按直连使用。AdsPower 代理池选项不适用于本机模式。

## 安全提示

- 只操作你本人拥有或明确获授权管理的账号。
- 服务没有登录认证；保持监听 `127.0.0.1`，不要直接暴露到局域网或公网。
- 账号密码、TOTP、Cookie、手机号和卡片信息目前均为本机明文存储。不要在共享电脑上运行，建议使用磁盘加密和受控的离线备份。
- 不要提交 `data/*.json`、页面转储、截图、日志、备份目录或 `.env`。
- 自动登录和并发访问可能触发风控。先从并发 `1` 开始，遇到验证码或额外验证时改为人工处理，不要持续重试。
- 换 2FA、添加/移除验证电话、年龄验证和关闭支付资料属于高风险写操作，可能不可逆；执行前请备份数据并确认账号恢复手段。
